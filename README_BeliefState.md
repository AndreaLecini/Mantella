# Belief State Node for Mantella

An extension of [Mantella](https://github.com/art-from-the-machine/Mantella) that introduces
an explicit, persistent registry of NPC beliefs, aimed at reducing narrative inconsistencies
(*panic switching*) in LLM-driven conversations in *The Elder Scrolls V: Skyrim*.

Developed as part of the thesis *Belief State* — Andrea Lecini, Politecnico di Torino.

---

## The problem addressed

Mantella manages an NPC's long-term memory through a text summary, updated and truncated
whenever the conversation exceeds the context window. This management has no semantic
criterion: a commitment made at the start of the conversation is just as likely to be
dropped as an irrelevant exchange from the same moment. The result is that the NPC can
contradict its own commitment, its own statement, or its own attitude toward the player with
no narrative justification whatsoever.

This project does not replace Mantella's memory management: it **complements** it with a
structured registry that separately preserves what must remain accurate.

---

## What was added

All new code lives under `src/beliefstate/` and integrates into Mantella's existing pipeline
without modifying its HTTP transport or the JSON message format between `SKSE` and the
FastAPI server.

| Module | Function |
|---|---|
| `entities.py` | Closed registries of entities and predicates, cascade rule table |
| `dag.py` | Graph structure (nodes, edges, container) |
| `engine.py` | Proposition insertion, conflict detection and resolution, cascade propagation, commitment transitions |
| `extraction.py` | Claim extraction constrained to the closed schema |
| `manager.py` | Per-entity graph persistence, across sessions and turns |
| `verifier.py` | Post-generation verification of the model's response |
| `serialization.py` | JSON serialization/deserialization of the graph to disk |
| `prompt.py` | Conversion of relevant propositions into compact text for the prompt |

### New components in the conversation pipeline

Compared to Mantella's original flow (`Conversation` → `Prompt Builder` → `LLM client` →
`Chat Manager`), the pipeline gains four stages:

```
turn input
   │
   ▼
Claim Extraction  ──────────► extracts typed propositions from the current turn
   │
   ▼
Contradiction Detector  ───► detects direct (Type I) and cascading (Type II) conflicts
   │
   ▼
Belief State  ──────────────► persistent graph of resolved propositions
   │
   ▼
Prompt Builder (extended)  ─► injects the relevant propositions as a belief_state variable
   │
   ▼
LLM client (unchanged)
   │
   ▼
Action Verifier  ───────────► extracts claims from the response, checks them against the graph
   │                           if consistent: selective consolidation
   │                           if inconsistent: discard and fallback
   ▼
Chat Manager (unchanged) → TTS
```

### Graph node structure

Each node represents a single proposition:

```
id                   unique system-generated string
type                 Fact | Intention | RelationalState | Commitment
predicate            value from the closed registry (determines the subject/object/value domains)
subject, object      references to the entity registry, never free-form strings
value                boolean or restricted enumeration, defined by the predicate
status               ACTIVE | SUPERSEDED
commitment_status    PENDING | FULFILLED | VIOLATED   (Commitment type only)
source_type          ENGINE | PLAYER_DIALOGUE | DERIVED_CASCADE | LLM_GENERATED
created_at           timestamp on the in-game calendar
```

A single edge type, `depends_on`, created exclusively for propositions generated by a
cascade rule, pointing to the proposition that originated them.

### Closed registries (experimental scenario configuration)

```
Actors:      Player, Lydia, Aela, Belethor, Agnis
Objects:     ancestral sword, iron axe, dagger, golden ring
Predicates:  POSSESSION, BETRAYAL, TRUST, INTENTION_TO_FOLLOW, COMMITMENT
```

Extending the registry to new scenarios requires manually editing `entities.py`: the system
does not derive the vocabulary from the game's content.

### Resolution policy

In the event of a direct conflict (same `type, predicate, subject, object` key, different
value), the proposition with the higher-tier `source_type` wins; ties are broken by
recency. Source hierarchy, from most to least reliable:

```
ENGINE > PLAYER_DIALOGUE > DERIVED_CASCADE > LLM_GENERATED
```

Resolution always happens before the call to the model and is never delegated to the model
itself.

## What was changed in Mantella's existing code

- **LLM client**: added a configurable custom model for extractions, set via the config ini
  file.
- **Prompt Builder**: extended with a new template variable, `belief_state`, which receives
  the compressed block of relevant propositions generated by `prompt.py`. Mantella's
  original text summary was not removed: the two sources coexist, with the summary now able
  to be compressed more aggressively since the binding facts are already guaranteed by the
  graph.
- **Input pipeline**: added the `Claim Extraction` step and conflict resolution/insertion
  into the belief state graph.
- **Response pipeline**: added the `Action Verifier` step between receiving the model's
  response and delivering it to the `Chat Manager`.

```

Mod Organizer 2
Mantella (run from source)
Python 3.11
Extraction models tested: qwen2.5:3b, qwen2.5:7b, gpt-oss:120b (local via Ollama / cloud)
```

Test environment: a dedicated interior cell built with the Creation Kit, NPCs duplicated
from the originals and adapted to the scenarios, dedicated quests to guide user experiments.

## Known limitations

- **Manual registry authoring.** Extending entities and predicates to a new scenario
  requires hand-editing `entities.py`; the system does not derive them from the game's
  content.
- **Latency cost.** Claim extraction and verification are blocking calls to the model and
  introduce a per-turn overhead relative to the Mantella baseline (measured in the thesis,
  Results chapter). Planned mitigation: making extraction asynchronous with respect to
  speech synthesis.
- **Experimental coverage.** The user experiments validate a single narrative arc
  (commitment made / broken); the generality of the registry to other relational dynamics
  (persuasion, corruption) has not been empirically verified.
- **Long-term graph scalability.** The sessions tested cover at most about a hundred turns;
  it has not been verified whether, over a campaign spanning tens of hours, graph growth
  would compromise resolution time or prompt compactness.

---

## Persisted file structure

Each NPC's graph is serialized to JSON at the end of the conversation and reloaded at the
start of the next encounter, per entity, ensuring cross-session persistence.
